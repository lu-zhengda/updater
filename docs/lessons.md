# Release lessons

Each row is a failure that reached a tag, a tap commit, or a green publish job. The check in the last column fails on that failure. An instruction in `AGENTS.md` is not the check.

| Mistake | Date | Rule | Enforced in |
| --- | --- | --- | --- |
| `parseBrewInfo` rejected an empty cask version, then stripped a composite suffix. A version of `,` or `,218372` became empty and was returned as a successful parse. | 2026-11-13 | A cask version is the text before the first comma, and that text must be non-empty. `sha256 :no_check` still yields an empty digest. | `TestParseBrewInfo` in `internal/checker/brew_info_test.go` and `FuzzParseBrewInfo`, CI job `Test` |
| `CleanTagVersion` stripped a leading `v` before the longer prefixes, so a tag `version-1.2.3` became `ersion-1.2.3` and `ver-1.2.3` became `er-1.2.3`. Those strings are not the version. The prefixes are what the helper and the GitHub checker compare and what names `updater_<version>_darwin.tar.gz`. | 2026-11-13 | One listed prefix is removed as a whole token, longest match first: `version-`, `version/`, `release-`, `release/`, `ver-`, `ver/`, then `v`. | `TestCleanTagVersionPrefixes` in `internal/checker/github_test.go`, CI job `Test` |
| The self-update helper replaced `Updater.app` with two `os.Rename` calls, and a failed Homebrew upgrade moved the bundle aside before moving the backup back. A kill between those renames left no app at the install path. The direct-install path already used one `renamex_np(RENAME_SWAP)`. | 2026-11-13 | The installed bundle and the staged candidate are exchanged by one `RENAME_SWAP`. A failed swap leaves the installed app where it was. A failed cask upgrade swaps the backup into place the same way. | `TestReplaceUpdaterBundleSwaps` and `TestRestoreUpdaterBundleSwaps` in `cmd/updater/self_upgrade_test.go`, CI job `Test`. TLC config `mutate-two-rename.cfg` fails `AlwaysPresent` if the two-rename sequence comes back, CI job `formal`. |
| GoReleaser wrote both `depends_on :macos` and `depends_on macos: :tahoe`. Current Homebrew refused to load the cask. v0.24.0, v0.24.1, and v0.24.2 shipped that file. PR #30 fixed it in v0.24.3. | 2026-11-12 | The generated cask loads in current Homebrew as macOS >= 26. A cask that contains both macOS stanzas does not load. | `scripts/homebrew-cask-macos_test.sh` in CI job `Test DMG packaging` |
| `completions/` is gitignored, so the release tarball omitted the files the cask links. `brew install` and `brew upgrade` rolled back. v0.24.3 shipped that tarball. PR #31 fixed it in v0.24.4. | 2026-11-13 | The tarball contains `completions/updater.bash`, `completions/updater.zsh`, and `completions/updater.fish`, and `brew install` of the generated cask links them. | `scripts/cask-archive-proof.sh` via `scripts/cask_archive_proof_test.go` in CI job `Test` |
| v0.24.0 through v0.24.3 published casks that could not be installed, and no job installed the published cask. | 2026-11-12 | Before publish, CI installs the generated cask from its tarball. The cask `sha256` must already match that tarball. After publish, `verify-updater` installs and upgrades `lu-zhengda/tap/updater`. | `scripts/cask-archive-proof.sh` in CI job `Test`; `scripts/cask-checksum.sh` called from `scripts/mkdmg_test.sh` in CI job `Test DMG packaging`; `brew-install` and `brew-upgrade` in `.cursor/skills/verify-updater/scripts/verify-updater.sh` |
| `scripts/mkdmg.sh` required executable `/usr/bin/xcrun` and `/usr/bin/spctl`. On the GitHub-hosted runner those paths are missing (`spctl` is `/usr/sbin/spctl`). Publish run [43149391974](https://github.com/lu-zhengda/updater/actions/runs/43149391974) notarized the app and then died. PR #28 fixed the lookup. | 2026-11-12 | When `NOTARIZE=1`, `xcrun` and `spctl` are the first executable files on `PATH`. A missing or non-executable `/usr/bin` copy does not hide them, and a tool missing from `PATH` fails the DMG build. | `scripts/mkdmg_test.sh` in CI job `Test DMG packaging` |
| Tag `v0.24.1` points at `cc769931b0963f3373fe4850df771e24afc30881` and has no GitHub Release. The merge workflow created the tag, then the publish job failed. | 2026-11-12 | Every `vX.Y.Z` tag except the single newest unreleased tag has a GitHub Release. `v0.24.1` is the one allowlisted tag, in `scripts/known-orphan-tags.txt`, because the tag stays. | `scripts/orphan-release-tags.sh`, called from `scripts/mkdmg_test.sh` in CI job `Test DMG packaging` (`scripts/orphan-release-tags_test.sh` fails the v0.24.1 case when the allowlist is empty) |
| The v0.6.0 release put `updater` and `updater-menubar` in one archive and the archive name collided. Runs [22028773898](https://github.com/lu-zhengda/updater/actions/runs/22028773898), [22028802589](https://github.com/lu-zhengda/updater/actions/runs/22028802589), and [22028818538](https://github.com/lu-zhengda/updater/actions/runs/22028818538) failed. | 2026-02-15 | `updater-archive` contains only the `updater` build. `allow_different_binary_count` and `updater-menubar` are not in that archive. `.goreleaser.yaml` sets `CGO_ENABLED=1` (run 22028802589 failed the menu-bar build without cgo). | `scripts/cask-shape.sh`, called from `scripts/mkdmg_test.sh` in CI job `Test DMG packaging` |
| The 0.16.0 cask dequarantined `Updater.app` and left the loose CLI quarantined, so Gatekeeper killed it and the `bin` symlink dangled. Homebrew also aborted when `/Applications/Updater.app` was not one it had installed. Commit `cec54e9fc753` hotfixed the live tap. Commit `0d65d71c714d` then pointed the cask binary at the stapled app. | 2026-07-18 | The cask links `#{appdir}/Updater.app/Contents/MacOS/updater`, removes a pre-existing `Updater.app`, and does not strip `com.apple.quarantine`. | `scripts/cask-shape.sh`, called from `scripts/mkdmg_test.sh` in CI job `Test DMG packaging`; the installed link is checked by `scripts/cask-archive-proof.sh` |
| Homebrew 7 rejected the cask `system_command` install hook. Commit `c0cbfb3fa994` and tap commit `d03aa206e` replaced it with `remove`. | 2026-09-15 | Cask hooks do not call `system_command`. | `scripts/cask-shape.sh`, called from `scripts/mkdmg_test.sh` in CI job `Test DMG packaging` |
| Notarization and stapling were not one gate in front of the upload. Run 43149391974 stapled the app and never validated a DMG. Releases before PR #22 (2026-11-12) were not Developer ID signed. | 2026-11-12 | Before GoReleaser writes archives or publishes, `CFBundleShortVersionString`, `CFBundleVersion`, and `updater --version` equal the tag. When `NOTARIZE=1`, `codesign --verify --deep --strict`, `spctl -a -vvv -t exec`, and `xcrun stapler validate` pass for the app, and `codesign --verify`, `xcrun stapler validate`, and `spctl --assess --type open` pass for the DMG. | `scripts/release-preflight.sh`, the last `universal_binaries` post hook in `.goreleaser.yaml`, inside release-publish job `release` before the GitHub Release and the tap push |
| Nuvio Desktop's GitHub tag `0.1.33-alpha` did not match `CFBundleShortVersionString` `1.1.33`, so the update was invisible. Issue #18, fixed by PR #19. | 2026-10-31 | A GitHub source can read the version from the zipped bundle, or apply a tag pattern, and the default tag comparison stays available. | `TestIntegration_GitHubVersionOverride` in `internal/updater/integration_test.go`, CI job `Test` |
| Sparkle feeds and Office casks reported updates by comparing a short version with a build version. Issue #12, fixed by `5924e0db21d3`. | 2026-10-18 | Sparkle build metadata and cask version formats are compared as the same kind of version. | `TestSparkleChecker_BuildVersions` in `internal/checker/sparkle_test.go` and `TestBrewInfoChecker_BuildVersions` in `internal/checker/brew_info_test.go`, CI job `Test` |
| PR #22 merged the signing and notarization scripts with no semver label. A merged pull request with no semver label makes `release-on-merge` succeed and skip publish (`scripts/plan-release-tag.sh`; run [43476397132](https://github.com/lu-zhengda/updater/actions/runs/43476397132) skipped `release`). | 2026-11-12 | A pull request that changes shipped Go, packaging, the release workflows, or the release scripts, and has no `semver:patch`, `semver:minor`, or `semver:major` label, gets a warning annotation. Docs-only and test-only changes do not. The warning does not fail the job and is not an approval gate. | `scripts/shipped-label-warn.sh`, called from `scripts/mkdmg_test.sh` in CI job `Test DMG packaging` |
