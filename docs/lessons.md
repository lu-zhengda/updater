# Release lessons

Each row is a failure that reached a tag, a tap commit, or a green publish job. The check in the last column fails on that failure. An instruction in `AGENTS.md` is not the check.

| Mistake | Rule | Enforced where |
| --- | --- | --- |
| Go findings from errcheck, staticcheck, unused, and gocritic had no CI gate. The tree already has more than 200, mostly unchecked fmt writes and Close calls, and editing those call sites would churn the app without changing its behavior. | The existing CI test job runs golangci-lint with errcheck, staticcheck, unused, nolintlint, and gocritic on the hosted macOS runner with cgo enabled, so the Objective-C files type-check. nolintlint requires the directive to name a linter and give a reason. The run reports issues introduced since the pull request base, or since the previous commit on a push to main. A finding on a changed line fails the job. | `.golangci.yml` and the Lint step in `.github/workflows/ci.yml` job `test` (`--new-from-rev`) |
| Comments that are not API documentation or an external constraint had no cap. The tree has 1201 disallowed comment lines. | A comment line is allowed when it is a license header before `package`, a doc comment on an exported identifier, a line whose text starts with `platform:` (a constraint forced by an outside platform or protocol), a Go toolchain directive (`//go:`, `// +build`, `//export`, `//line`, or a cgo or C preprocessor line), or a line that links a GitHub issue or pull URL or a Linear issue URL. A line of executable code inside the comment block before `import "C"` is not a comment. Every other line counts. The committed per-file counts must match the tree. A count above the previous baseline, a new file with any counted line, or a baseline left higher than the tree fails. | `go run ./internal/tools/commentcheck` via `scripts/comment-ratchet.sh` in CI job `test`, with `TestNewFilePlainCommentFails` in `internal/tools/commentcheck/scan_test.go` |
| A GUI or integration test that runs against a protected user folder hangs on a macOS privacy prompt. | Live desktop and direct-install tests update a temporary copy of the app. They do not launch or replace an installed copy. | `TestLiveDesktopDMGInstall` in `internal/installer/desktop_live_test.go`; `TestLiveNuvioDirectInstall` and `TestLiveVSCodeDirectInstall` in `cmd/updater` (`liveInstallRunner` returns an error for `open`) |
| A test that writes a login-item plist into the real home directory, or that installs over an installed copy, changes the machine under test. | Menu-bar and schedule tests write LaunchAgent plists under a temporary home. Live install tests copy the target into a temporary directory. They do not replace an installed copy. | `cmd/updater/menubar_test.go`, `cmd/updater/schedule_test.go`, and the live install tests named above |
| Orphaned test builds once kept the menu bar and blocked the installed app for days. | A hands-on run quits the app instances it started, force-detaches the disk images it mounted, and fails when a stage directory or a temp path it created is still there. | `remove_run_artifacts` and `check_no_strays` in `.cursor/skills/verify-updater/scripts/verify-updater.sh`. Yield rules for a peer from a volume or a temporary directory stay on the single-instance row. |
| A branch showed no checks until its pull request was open. A workflow that also ran on other branches or on a schedule would hide that. | CI runs on a pull request against main and on a push to main. It does not run on a schedule. A branch has no checks until its pull request is open. | `on` in `.github/workflows/ci.yml`, asserted by `scripts/pr-standard_test.sh` |
| 2026-11-22. The single-instance guard from PR #48 (ZHE-60) treated every other `com.updater.app` accessory peer as the owner. Orphan test instances from a mounted DMG under `/Volumes/Updater` and a deleted temp path under `/private/var/folders/.../T/` kept the menu bar for 9 days, ran YOLO twice, and made `/Applications/Updater.app` exit at launch. Linear ZHE-69. | The installed copy (`/Applications`, `~/Applications`, or Homebrew `Caskroom/updater`) or a strictly newer version wins. A peer from `/Volumes`, a temp dir, or a missing executable path yields: the preferred newcomer terminates it, and a stale instance also quits on each check cycle when an installed copy is running or its own path vanishes. Two installed copies of the same version still yield (newcomer exits). | `TestDecideMenubarInstance` and `TestClassifyMenubarPath` in `cmd/updater/single_instance_test.go`, CI job `Test` |
| 2026-11-13. A Gatekeeper first-launch prompt left the verify harness waiting on a process that never left `_dyld_start` and never used CPU. The in-app update was not exercised. After the prompt was approved, the same 0.24.7 binary reached `NSApplication`. | Do not click macOS security dialogs. If a harness launch stays in `_dyld_start` with about 0 CPU, syspolicyd logs `Prompt shown ... waiting for response` for `com.updater.app`, or the copy's quarantine flags lack `0x40`, `launch`, `self-update`, and `menu-update` print `INCONCLUSIVE` and stop within the bounded wait. Clear `com.apple.quarantine` only on a copy the harness created under its work directory, or on `~/Applications/Updater.app` after this run placed that copy. Never clear it on `/Applications/Updater.app` or another user copy. | `--self-test` in `.cursor/skills/verify-updater/scripts/verify-updater.sh`, run by `TestVerifyUpdaterGatekeeperSelfTest` |
| 2026-11-13. Verification runs left temp copies, DMGs, helper directories, and `/Applications/.updater-self-*` stage directories on the Mac. A script that is useful again belongs in the repo and is run from the checkout. | `verify-updater.sh` records every temp path it creates and removes those paths on exit. The run then fails if a `.updater-self-*` directory remains beside `/Applications` or `~/Applications`, if a `verify-updater*` temp path remains, or if the workspace has an untracked or ignored file outside `.cursor/skills/verify-updater/scripts/cleanup-allowlist.txt`. Evidence logs under `~/Library/Logs/verify-updater/` stay. | `cleanup` in `.cursor/skills/verify-updater/scripts/verify-updater.sh` |
| 2026-11-13. The cask-version guard read `brew info --cask --json=v2` without refreshing the tap. `brew info` does not auto-update, so right after a release the local tap still had the previous cask. In-app update then failed with `refusing brew upgrade: cask version 0.24.5 is lower than target 0.24.6 or installed 0.24.5`. Before that guard, `brew upgrade` auto-updated and installed the release. v0.24.6. | Under `update.lock`, fast-forward the Updater tap with `git fetch` of its tracked upstream and `git merge --ff-only` before reading the cask version. Do not reset the checkout. If the fetch or the fast-forward fails, still read the version. Do not run `brew upgrade` when the cask is lower than the installed app or lower than the GitHub target, including a cask newer than the installed app but still behind the target. That wait is not a failed install. | `TestSelfUpgradeRefreshesStaleTap` and `TestSelfUpgradeRefusesLowCaskVersion` in `cmd/updater/self_upgrade_test.go`, CI job `Test` |
| 2026-11-13. The Homebrew self-update called `brew upgrade` when the cask version could be older than the GitHub release or the installed app, and a `brew upgrade` that removed `Updater.app` left no restore on the next launch. The model trace installed version 1 after version 2 because the cask version and the GitHub tag are not the same number. | Brew owns the cask install. Do not copy a bundle into the Caskroom or rewrite the receipt. Before `brew upgrade`, refuse a cask version lower than the target release or the installed version, and hold `update.lock` until brew returns. After brew returns, check the Developer ID signature and the bundle version, and restore the ditto backup on failure. On the next run or launch, restore that backup when the app is missing or unsigned. | `TestSelfUpgradeRefusesLowCaskVersion`, `TestSelfUpgradeBrewRestoresAfterBadResult`, and `TestRecoverStrandedUpdater` in `cmd/updater/self_upgrade_test.go`, CI job `Test`. `sh .cursor/skills/verify-updater-formal/scripts/run.sh` fails `NoDowngrade` on TLC config `mutate-skip-cask-version.cfg` if the cask-version guard is removed, and fails `TestRecoverStrandedUpdater` if the restore is removed. |
| 2026-11-13. `parseBrewInfo` rejected an empty cask version, then stripped a composite suffix. A version of `,` or `,218372` became empty and was returned as a successful parse. | A cask version is the text before the first comma, and that text must be non-empty. `sha256 :no_check` still yields an empty digest. | `TestParseBrewInfo` in `internal/checker/brew_info_test.go` and `FuzzParseBrewInfo`, CI job `Test` |
| 2026-11-13. `CleanTagVersion` stripped a leading `v` before the longer prefixes, so a tag `version-1.2.3` became `ersion-1.2.3` and `ver-1.2.3` became `er-1.2.3`. Those strings are not the version. The prefixes are what the helper and the GitHub checker compare and what names `updater_<version>_darwin.tar.gz`. | One listed prefix is removed as a whole token, longest match first: `version-`, `version/`, `release-`, `release/`, `ver-`, `ver/`, then `v`. | `TestCleanTagVersionPrefixes` in `internal/checker/github_test.go`, CI job `Test` |
| 2026-11-13. The self-update helper replaced `Updater.app` with two `os.Rename` calls, and a failed Homebrew upgrade moved the bundle aside before moving the backup back. A kill between those renames left no app at the install path. The direct-install path already used one `renamex_np(RENAME_SWAP)`. | The installed bundle and the staged candidate are exchanged by one `RENAME_SWAP`. A failed swap leaves the installed app where it was. A failed cask upgrade swaps the backup into place the same way. | `TestReplaceUpdaterBundleSwaps` and `TestRestoreUpdaterBundleSwaps` in `cmd/updater/self_upgrade_test.go`, CI job `Test`. `sh .cursor/skills/verify-updater-formal/scripts/run.sh` fails `AlwaysPresent` on TLC config `mutate-two-rename.cfg` if the two-rename sequence comes back. |
